## Cross-cluster source consistency check

- The Teams cluster (`teams.md`) cites the same `group-set-options#configure-groups` page for `resourceBehaviorOptions` and the same `New-PnPTeamsTeam` doc. No contradictions between our cluster's reading and the Teams cluster's reading of `WelcomeEmailDisabled`.
- The SharePoint cluster (`sharepoint-sharing.md`) flags a PnP doc defect on `-SendInvitation` (inverted boolean description). Our cluster did not encounter that bug because our `-SendInvitationMessage` review used the Graph + MgGraph docs, not the PnP `Add-PnPFileSharingInvite` page. Cross-reference for the SA: the bool semantics for Graph `/invitations` are correctly documented (`true` = mail sent).
- The forensics cluster (`audit-forensics.md`) treats the 52-user incident as evidence-gathering. Our cluster's working hypothesis (**guest-autosubscribe-trap × Exchange welcome enabled**) is consistent with the SharePoint cluster's leading hypothesis (**`-SendInvitation` true on file/folder sharing**); both should be cross-validated against the audit-log evidence the forensics cluster surfaces.

## What was NOT verifiable from docs alone

Flagged for empirical canary, per `m365-groups-b2b-xtsync.md` §3e:
1. Whether xtsync provisioning is *still* silent in 2026 if downstream automation immediately adds the synced user to an M365 Group. (Docs say yes, field reports vary.)
2. Whether `userSyncInbound: false → true` re-fires anything. (Docs silent.)
3. Whether the `WelcomeEmailDisabled` resource-behavior flag is honoured 100% when the member-add happens *seconds after* the group POST. (Race-condition test recommended for any high-throughput script.)
